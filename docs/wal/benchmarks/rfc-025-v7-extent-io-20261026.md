# RFC 025: larger v7 extent-initialization writes, 2026-10-26

**Result: reject and restore the 128-KiB implementation. Larger writes lower readiness cost in the fastest pair, but fail the fixed SSD throughput and p99 guards. The eleven retained optimizations remain.**

This follows the [allocator trials](rfc-025-v7-mimalloc-20261026.md), where RAM gains did not establish an SSD improvement. Three fresh, excluded retained-binary CPU profiles and the engine's stage timers precede this I/O experiment. The profiles record `cpu-clock:u`; they do not measure kernel time or off-CPU I/O latency. The [event record](artifacts/rfc-025-v7-extent-io-20261026-profile-events.json) preserves the requested and actual events.

## Candidate and protocol

The retained v7 path synchronously initializes new 1-MiB extents in up to eight 128-KiB aligned writes. This candidate changes only v7's initialization chunk to 512 KiB, giving up to two synchronous writes for that range. The shared immutable aligned zero source grows by 384 KiB. V4 retains its 128-KiB background initializer; tmpfs remains allocation-only. The shared preparation lock, exact initialized range, partial-cap handling, large-DATA allocation-only path, release publication of readiness, error poisoning and one-WAL-sync protocol stay unchanged. It does not initialize an extra speculative range.

The host is Linux 6.12.71-1-lts, ext4 on a Solidigm SSDPFKNU010TZ, with an i9-13900T and 32 logical CPUs. Both `max_hw_sectors_kb` and `max_sectors_kb` read 512. These are block-layer limits, not a promise that a 512-KiB userspace write becomes one hardware command. See the [kernel block-device ABI](https://cdn.kernel.org/doc/html/latest/admin-guide/abi-stable.html). No device settings change. The [environment record](artifacts/rfc-025-v7-extent-io-20261026-environment.json) retains the actual queue values.

The [plan](artifacts/rfc-025-v7-extent-io-20261026-plan.json) is fixed before source changes and scoring. Each SSD workload has four warmups and five alternating four-arm rounds: retained/candidate v4 controls and retained/candidate v7. Both use eight writers, 1-KiB values and a 2-GiB SST target. Point writes use 100,000 puts and sample every 100 operations; batch64 uses 750,000 puts and samples every ten batches. There is a 30-second initial cooldown and ten seconds between runs.

Both workloads require raw paired, v4-normalized and arm-median throughput ratios of at least 0.95, and paired p99 at most 1.10. At least one must gain 2% raw with normalized throughput at least unchanged. Only passing SSD results would trigger the three RAM guards and a fixed additional five-pair SSD confirmation. The SSD phase fails, so those conditional captures are cancelled.

All **40 scored records, eight warmups, 48 unique IDs and 471 clear host samples** remain. The process audit runs before, once per second during, and after each command; it checks recognized competing builds, tests and benchmarks. No such process appears. Sampling cannot exclude every brief or unrelated task, and does not exclude SSD stalls. Every stalled run remains included.

## Results

Rates are per-arm medians; changes are medians of same-round ratios. Normalization is `(candidate v7 / candidate v4) / (retained v7 / retained v4)`.

| SSD workload | Retained / candidate median puts/s | Paired raw | V4-normalized | CPU | p99 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Point | 15,238 / 4,703 | -31.3% | -32.3% | +14.6% | +24.1% |
| Batch64 | 360,462 / 367,524 | +0.03% | +4.6% | +0.4% | -7.9% |

Point arm medians differ much more than the paired median because slow runs occur in different rounds. Retained v7 rates span 4,908–15,552 puts/s; the candidate spans 4,646–16,052. V4 controls' paired median change is -0.9%. These observations fail the acceptance rules; they do not isolate how much of the loss comes from code versus moving storage stalls.

The fifth point pair is fast in both arms. It changes from 15,552 to 16,052 puts/s (+3.2%), and measured packer preallocation time falls from 227 to 145 ms (-36.1%). Its accumulated `fdatasync` time remains about 3.2 seconds. This supports the narrow mechanism of reducing readiness waits, but does not override the other four pairs. Batch64 is effectively flat raw and does not meet the required material gain.

The highest matching scored rates, with warmups excluded, are:

| SSD workload | V4 control | Retained v7 | Candidate v7 |
| --- | ---: | ---: | ---: |
| Point | 17,253 | 15,552 | 16,052 |
| Batch64 | 390,705 | 383,348 | 392,085 |

The [peak identities](artifacts/rfc-025-v7-extent-io-20261026-peaks.json) retain the raw hashes and run IDs. Historical highs are separate cohorts and are not pooled into the decision. This experiment does not establish v4 parity or the complete Stage 8 performance gate.
